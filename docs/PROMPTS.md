# Ключевые промпты и решения

Это журнал реальных постановок задач в текущем чате. Цитаты ниже воспроизводят существенные фрагменты фактических сообщений; сокращения обозначены многоточием. Это не полный экспорт переписки. Полную переписку и снимки этапов для конкурсной подачи сохраняет капитан команды.

## 1. Пользователь: постановка задачи

> «Вот техническое задание для хакатона, ты в роли тим лида декомпозируй это тз для своих суб агентов, чтобы выполнить его и сделать отчет пока никуда не деплой, просто сделай рабочий проект, начни делать отчет, если будут вопросы по реализации или выбору чего-то то спращивай уточнения».

Приложенное ТЗ требует пять разделов, работу на телефоне от 360 px, минимум два аккаунта, вымышленные данные, защищённое хранение паролей и изоляцию данных. Это стало основой API.md, AGENTS.md и критериев приёмки.

## 2. Тимлид: уточнение стека

> «Есть ли предпочтения по стеку и вузу? Если нет, возьму вымышленный университет, название “Кампус”, React + Node.js + SQLite; все данные будут демонстрационными».

Пользователь выбрал ответ «Есть пожелания — напишу». Пока ожидалось уточнение, то, что node/npm не находились в PATH, привело к промежуточному выбору Python. Затем пользователь выбрал Go + React и окончательное название «Разумист». Эти предпочтения имеют приоритет над промежуточной реализацией. Позже Go и Node найдены вне PATH: первоначальное предположение об отсутствии установки было исправлено.

## 3. Тимлид → backend: изоляция и хранение

> «Создай server.py и backend-модули … Прочти AGENTS.md docs/API.md. … Реальный cookie auth PBKDF2, CSRF, ownership, безопасная раздача static, rate limit login, logout, persistent db … Два демо аккаунта, разные данные, заявки создание/отмена/история (не симулируй реальную обработку автоматически). … Не деплоить».

Это исходный промпт до уточнения стека. После выбора Go серверная задача переадресована на Go; требования безопасности и контракт сохранены. Существенное решение: статус новой заявки не продвигается сам по таймеру и не выдаётся за обработку настоящим деканатом.

## 4. Тимлид → frontend: сценарии и визуальный язык

> «… красивый законченный русский кабинет … Дизайн: тёплый светлый фон, тёмный navy сайдбар, зелёный акцент, выразительная типографика системными шрифтами; современный продукт. Вход два демо аккаунта, главная с ближайшей парой/сводкой/уведомлениями/быстрыми действиями; расписание день/неделя с датами и изменениями, оценки с прогрессом и сессией, заявки форма+история+отмена+статусы, уведомления read, профиль, logout. Мобильный 360 px полноценный, accessible labels, error/loading/empty … Везде концепт/вымышленные данные. Не деплоить».

Исходное требование браузерного JavaScript без зависимостей затем заменено React согласно выбору пользователя. Визуальное направление и сценарии сохранены.

## 5. Тимлид → QA и отчёт

> «Создай tests/test_api.py на unittest, запускающий сервер с временной БД; meaningful тесты входа, двух аккаунтов, изоляции заявок, CSRF, logout, сохранения данных, ошибок. … Отчёт русский честный черновик с фактическими промптами/распределением ролей, критериями и планом скриншотов, без выдумки завершённых проверок».

Тесты обращаются к реальному HTTP-серверу и используют отдельную временную базу. Проверки не ограничиваются успешным входом: второй студент пытается получить и отменить чужую заявку, прочитать чужое уведомление; затем проверяются выход и сохранение данных после перезапуска.

## 6. Корректировка после уточнения пользователя

Сообщение тимлида субагенту QA:

> «ВАЖНО пользователь выбрал Go + React, название “Разумист” (именно последнее). Обнови отчёт/декомпозицию. Backend переписывается Go, контракт сохраняется. Python unittest можно сохранить как внешние API тесты … Зафиксируй смену выбранного стека как реальный этап».

Это пример корректировки решения по обратной связи, а не завершённого неудачного дизайна. Изображения и результаты пользовательского исследования не выдумывались.


## 7. Проверка и исправления

QA сообщил тимлиду о прохождении HTTP-тестов и о том, что первоначальный запуск suite упёрся в ограничение частоты входов. Тесты переведены на отдельный процесс сервера для каждого сценария, сохраняя временную SQLite между перезапусками. Серверный агент дополнительно сообщил:

> «Rate limit 10 попыток/мин на IP + логин; успешный вход сбрасывает счётчик именно этой пары».

Добавлена отдельная проверка ограничения попыток входа. Итог подтверждён запуском: 12 тестов, `OK`. На ревью тимлид также нашёл блокировку входа, которую backend исправил до интеграции. Конкретные логи или скриншоты этих этапов ещё нужно приложить к конкурсной версии отчёта.

## Финальная интеграция тимлидом

При ревью интерфейса были поставлены уточнения: заменить обещание передачи заявки настоящему деканату честным описанием прототипа; перевести категории уведомлений на русский; обеспечить Escape, удержание и возврат фокуса в диалогах; сбрасывать состояние окон при смене аккаунта; заменить inline-стили прогресса на native progress для строгой CSP. После браузерной проверки скрытая мобильная навигация исключена из доступного дерева, исправлены формы числительных. Реальные снимки сохранены в screenshots/. Инструменты финальной проверки: встроенный браузер CUA, viewport 360×800 и 1440×1000; Prettier для читаемого форматирования; официальный Node.js для обхода несовместимости подписи встроенного runtime с Rollup (защитные настройки системы не менялись).
