# Декомпозиция ТЗ: «Разумист»

Рабочий документ тимлида. Дата начала: 6 ноября 2026 года, МСК. Режим: только локальная разработка, без деплоя.

## Цель и границы

Создать работающий личный кабинет студента: вход → сводка учебного дня → расписание и оценки → подача заявки → проверка статуса. Предусмотреть второй независимый аккаунт и мобильный экран от 360 px. Университет, студенты, преподаватели и учебные данные вымышлены. Кабинет сотрудника, реальная выдача документов, интеграции с вузом и размещение в интернете в текущую итерацию не входят.

## Распределение работы

| Ответственный | Зона файлов / задача | Результат и критерий приёмки |
| --- | --- | --- |
| Главный агент / тимлид | Архитектура, API-контракт, AGENTS.md, README, приёмка, интеграция | Единый локальный запуск, согласованные сервер и клиент, проверенный основной сценарий, честно указанные ограничения |
| Субагент backend | Go-сервер, SQLite, сессии и начальные данные | Вход двух студентов, серверная изоляция, хеши паролей, сохранение заявок и прочтения уведомлений, CSRF, выход |
| Субагент frontend | React, компоненты и стили | Пять обязательных разделов, профиль, адаптивная навигация, понятные состояния загрузки/ошибок/пустых списков |
| Субагент qa_report | tests/test_api.py, этот документ, REPORT.md, PROMPTS.md | Внешние HTTP-тесты безопасности и сохранения данных; отчёт о реальном процессе и журнал ключевых промптов |

Агенты работают в одном каталоге. Границы владения файлами разделены, общий контракт находится в API.md. Изменения контракта согласуются с тимлидом. Итоговую интеграцию и оценку результатов выполняет главный агент.

## Пакеты работ

1. **Сформировать основу.** Зафиксировать ограничения конкурса, идентичность концепта, два тестовых аккаунта, модель данных, маршруты API и критерии приёмки. Спросить предпочтения пользователя.
2. **Сделать сервер.** SQLite, PBKDF2, HttpOnly cookie, проверка владельца на каждом доступе к персональным данным, валидация входа, заявок и действий. Персистентность после перезапуска.
3. **Сделать интерфейс.** Вход, главная, день/неделя расписания, успеваемость и сессия, заявки с историей, уведомления, профиль. Собственный текстовый знак без логотипа реального вуза.
4. **Интегрировать.** React использует реальные API; студент из сессии, а не из переданного клиентом ID. Заявка появляется в списке и сохраняется после обновления страницы.
5. **Проверить.** Позитивные и негативные HTTP-сценарии, два аккаунта, подмена ID, CSRF, выход, перезапуск. В браузере — сквозной путь и ширина 360 px. Результаты фиксировать отдельно от плана.
6. **Собрать доказательства.** Снимки интерфейса и разработки, ключевые промпты, описание защиты и ручных действий. Дополнить отчёт фактическими проверками. Публикация и отправка на конкурс — отдельный будущий этап после решения пользователя.

## Приоритеты

- P0: вход, изоляция двух аккаунтов, пять разделов, сохранение заявки, локальный запуск.
- P1: адаптивность, доступность, наглядные переносы занятий, история заявки, обработка ошибок.
- P2: расширение функций, видео, экспорт конкурсного отчёта; только после приёмки ядра.

## Изменения решений

Изначально тимлид предложил React + Node.js + SQLite. Проверка окружения сначала не обнаружила node/npm в PATH (позже Go и Node найдены вне PATH); промежуточно началась реализация на Python stdlib и браузерном JavaScript. После уточнения пользователя окончательно выбран **Go + React**, название — **«Разумист»**. Промежуточный сервер заменяется Go-реализацией, внешний HTTP-контракт и независимые тесты сохраняются. Python используется как инструмент запуска тестов, не как сервер приложения.
